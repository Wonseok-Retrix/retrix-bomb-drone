# 01. 하드웨어 준비 및 배선

Raspberry Pi AI Camera(Sony IMX500), 비행 컨트롤러(FC), 컴패니언 컴퓨터(라즈베리파이) 및 서보 드로퍼의 하드웨어 구성과 배선 방법입니다.

---

## 주요 부품 구성

| 구분 | 부품 | 비고 및 주요 역할 |
| :--- | :--- | :--- |
| **비행 컨트롤러(FC)** | MicoAir 743 v2 | PX4 펌웨어 탑재, 기체 자세 및 속도 제어 |
| **컴패니언 컴퓨터** | Raspberry Pi Zero W (또는 Zero 2 W) | 제어 명령 계산 및 MAVLink 송신 전담 |
| **AI 카메라** | Raspberry Pi AI Camera (Sony IMX500) | 온칩 신경망 객체 검출 (하방 장착) |
| **카메라 케이블** | 22핀(미니) ↔ 15핀 CSI 변환 케이블 | Zero 계열 전용 미니 커넥터 사용 |
| **서보 드로퍼** | 마이크로 서보 (SG90 등) + 투하 기구 | 과녁 자동 투하용 (2일차) |
| **배선** | 4핀 JST-GH (TELEM2용), 듀폰 점퍼 | FC ↔ Pi MAVLink 및 서보 신호선 |
| **SD 카드** | 16GB 이상, Class 10 이상 | 라즈베리파이 OS 탑재 |

---

## Raspberry Pi Zero W 활용 근거

신경망 연산(AI 추론)은 라즈베리파이가 아닌 **카메라 내부 IMX500 칩**에서 수행됩니다.

* **역할 분담**: IMX500 카메라는 물체 감지 좌표를 반환하고, Zero W는 이 좌표를 바탕으로 드론의 이동 속도 명령만 계산하여 MAVLink로 FC에 전달합니다.
* **시스템 최적화**: Zero W의 CPU 및 메모리 부담을 최소화하기 위해 아래와 같이 설정합니다.

| 항목 | 선택 설정 | 설정 이유 |
| :--- | :--- | :--- |
| **OS** | 32비트 Bookworm **Lite** | 512MB RAM 환경 최적화 (데스크톱 UI 제외) |
| **영상 처리** | **PIL + simplejpeg** | 무거운 OpenCV 대신 경량 라이브러리 사용 |
| **화면 확인** | **웹 브라우저** (`http://drone.local:8080`) | 헤드리스 환경에서 실시간 바운딩 박스 모니터링 |
| **GPU 메모리** | `gpu_mem=64` | 비디오 메모리 점유 최소화 |

---

## 프레임레이트 및 운용 방식

현재 사용 중인 AI 카메라 하드웨어는 **실측 1~2 fps**로 동작합니다.
따라서 `config.yaml` 설정은 1~2 fps 피드백 환경을 전제로 안정성을 최우선 고려하여 튜닝되어 있습니다.

| 운용 환경 | 설정 | 동작 특성 |
| :--- | :--- | :--- |
| **지상 튜닝 (화면 확인)** | `python3 tools/preview.py --fps 2` | 웹 브라우저로 감지 박스 및 제어 명령 모니터링 |
| **실전 비행 (프로펠러 장착)** | `config.yaml` (`camera.fps: 2`), `preview` 미실행 | 화면 출력 없이 제어기 계산 및 MAVLink 송신 전담 |

> [!IMPORTANT]
> - 카메라 fps와 MAVLink 전송 주기는 완전히 별개입니다. 카메라가 1~2 fps로 작동하더라도 MAVLink 명령은 `config.yaml`의 `send_rate` 설정(기본 10Hz)에 맞춰 차질 없이 지속 송신됩니다.
> - 하드웨어 세팅 완료 후 `python3 tools/check_camera.py`를 실행하여 실측 fps가 `config.yaml` 설정값(기본 2 fps)에 가깝게 출력되는지 반드시 확인하세요.

## 배선 1: AI 카메라 연결

* 22핀 미니 CSI 케이블을 사용하여 AI 카메라를 Raspberry Pi Zero W의 카메라 커넥터에 연결합니다.
* **케이블 방향**: 금색 접점이 **보드 아래쪽(바닥면)**을 향하도록 꽂아야 합니다.
* **주의**: Zero 계열은 표준 15핀 커넥터가 아닌 **22핀 미니 커넥터**를 사용하므로 전용 케이블을 준비하세요.

---

## 배선 2: Pi ↔ 비행 컨트롤러 (MAVLink 통신)

MicoAir 743 v2 FC의 **TELEM2** 포트와 라즈베리파이 GPIO 핀을 연결합니다.

```
   MicoAir 743 v2 TELEM2            Raspberry Pi Zero W
   ─────────────────────            ───────────────────
     5V   ───────────────────────►  물리핀 4  (5V)
     TX   ───────────────────────►  물리핀 10 (GPIO15 / RXD)
     RX   ◄───────────────────────  물리핀 8  (GPIO14 / TXD)
     GND  ───────────────────────   물리핀 6  (GND)
```

> [!WARNING]
> **TX와 RX는 반드시 교차(Cross) 연결**해야 합니다 (FC TX → Pi RX, FC RX → Pi TX). 배선 오류 중 가장 흔한 원인입니다.

> [!NOTE]
> Zero W는 기본 상태에서 블루투스 모듈이 하드웨어 UART(PL011)를 점유하므로 GPIO 14/15 핀에 보드레이트가 불안정한 mini UART가 할당됩니다.
> `tools/install.sh` 실행 시 블루투스가 비활성화되어 PL011이 GPIO로 복구되며, 포트 경로는 `/dev/serial0`이 됩니다. 자세한 사항은 [03. 비행 컨트롤러 설정](03-flight-controller.md#3-시리얼-포트-pi-연결)을 참조하세요.

## 배선 3: 서보 드로퍼 (과녁 투하용, 2일차)

서보 드로퍼 신호선은 **FC를 거치지 않고 라즈베리파이 GPIO 핀에서 직접 제어**하며, 전원(5V)만 FC 서보 레일에서 공급받습니다.

```
   FC 서보 레일 (또는 5V BEC)        서보              Raspberry Pi
   ─────────────────────────        ────              ────────────
     5V   ─────────────────────►  빨강 (VCC)
     GND  ─────────────────────►  갈색 (GND) ─────►  물리핀 6  (GND)
                                   주황 (신호) ◄────  물리핀 12 (GPIO18)
```

> [!WARNING]
> 1. **공통 접지(GND) 필수**: FC, 서보, 라즈베리파이 3자의 GND가 모두 연결되어야 합니다. 접지가 분리되면 신호 노이즈로 서보 떨림이나 오작동이 발생합니다.
> 2. **전원 공급 주의**: 서보 전원을 라즈베리파이 5V 핀에서 직접 공급받지 마세요. 서보 구동 시 순간 전류 감소로 라즈베리파이가 재부팅될 수 있습니다.
> 3. **FC 서보 레일 전원 확인**: MicoAir 743 v2의 서보 레일은 외부 BEC가 꽂혀 있어야 5V 전원이 출력됩니다. 멀티미터로 실제 전압을 측정하세요.

* **신호 핀 설정**: 기본 신호 핀은 GPIO18 (물리핀 12)이며, `config.yaml`의 `dropper.pin` 설정과 일치해야 합니다.
* **작동 점검**: 지상 점검 명령 `python3 tools/check_dropper.py`로 사전 확인하세요.

## 조립 및 장착 지침

* **카메라 방향**: 카메라는 **수직 하방(연직)**을 향하도록 장착합니다.
* **배선 안전**: CSI 플랫 케이블 및 듀폰 케이블은 프로펠러나 모터 회전부에 걸리지 않도록 케이블 타이어 등으로 단단히 고정하세요.
