# 04. 비행 & 파라미터 튜닝

하방 카메라 기반 자율 추적 비행 검증, 단계별 지상/비행 테스트 절차, 파라미터 튜닝 가이드 및 비행 안전수칙입니다.

---

## 1. 하방 카메라 장착 및 제어 원리

### 카메라 장착 지침
* 카메라는 **수직 하방(연직)**을 향하도록 장착합니다.
* **방향 일치**: **카메라 상단 표시가 드론 기수(전방)**를 향해야 합니다. 카메라 상/하 축이 드론의 전/후 이동 축과 일치해야 하며, 90° 회전 장착 시 좌우 이동 명령에 드론이 전후로 움직이는 오작동이 발생합니다.

### 제어 구조 (`src/controller.py`)

하방 카메라 영상의 위치 오차를 P 제어(비례 제어)를 통해 수평/수직 이동 속도 명령으로 변환합니다.

```
   목표가 화면 오른쪽에 위치   →   오른쪽으로 이동 (right > 0)
   목표가 화면 위쪽에 위치     →   앞으로 이동     (forward > 0)
   박스가 기준 크기보다 작음   →   고도 하강       (down > 0)
```

> [!NOTE]
> 본 제어기는 기체 회전(Yaw)을 수행하지 않으며(`yaw_rate = 0`), 기체가 수평으로 미끄러지듯 이동하여 목표 상공에 머무는 방식으로 동작합니다.

## 2. 1~2 fps 카메라 대응 제어 메커니즘

현재 AI 카메라 하드웨어는 **실측 1~2 fps**로 동작합니다.
한 번 검출된 위치 정보는 최대 1초간 갱신되지 않으므로, 동일한 속도로 계속 밀고 나가면 목표를 지나쳐(오버슈트) 좌우로 크게 흔들리는 헌팅이 발생합니다.

이를 방지하기 위해 명령에 **목표 정보의 나이(age)** 기반 감쇠(Decay)를 곱합니다:

```
나이 ≤ stale_hold (0.3초)       →   100% 명령 유지 (방금 본 정보)
stale_hold ~ stale_stop         →   선형 감쇠 (속도 줄임)
나이 ≥ stale_stop (1.2초)       →   0% (스스로 멈춰 다음 프레임 대기)
```

* **동작 방식**: **"한 장 보고 → 조금 이동하고 → 스스로 멈춰 다음 장 기다리기"**
* **설정 성격**: 추적 속도는 느리지만 구조적으로 오버슈트가 발생하지 않도록 정확도 대신 안정성을 택한 설정입니다.

### 실행 로그 읽는 법

감쇠 상태는 실행 로그의 `age`(정보의 나이)와 `x`(적용된 감쇠 비율)로 확인합니다.

```
[OK] x=+0.42 y=-0.11 size=0.21 conf=0.78 age=0.35s x0.94 -> fwd=+0.05 right=+0.16 down=+0.03m/s
```

`age`가 0에서 점점 커지다가 `x0.00`에 도달한 뒤 새 프레임이 들어와 다시 0으로 떨어지는 패턴이 반복되면 정상입니다. 카메라가 1~2 fps로 동작하고 있다는 뜻입니다.

### 카메라 속도가 개선되면

`tools/check_camera.py`로 실측 fps가 올라간 것을 확인한 뒤, 아래 순서로 되돌립니다. **한 번에 한 항목씩** 변경하고 테스트하세요.

| 순서 | 파라미터 | 조정 방향 |
| :--- | :--- | :--- |
| 1 | `camera.fps` | 실측값에 맞춰 설정 |
| 2 | `control.stale_hold` / `stale_stop` | 프레임 간격에 맞춰 축소 (예: 10 fps → `0.15` / `0.4`) |
| 3 | `tracking.lost_timeout` | `1.0` 수준으로 축소 |
| 4 | `control.lateral_gain` / `forward_gain` | `1.0`까지 단계적 상향 |
| 5 | `control.max_lateral` / `max_forward` | `1.0`까지 단계적 상향 |

## 3. 단계별 검증 절차 (순서 엄수)

> [!WARNING]
> **1~3단계 사전 점검 시 프로펠러를 반드시 완벽히 분리하세요.**

| 단계 | 검증 유형 | 실행 명령 | 주요 확인 및 검증 사항 |
| :--- | :--- | :--- | :--- |
| **1단계** | 책상 위 카메라 점검 | `python3 tools/preview.py` | `http://drone.local:8080` 접속 후 목표물 이동 시 `right`, `fwd` 제어 수치 부호 정상 동작 확인 |
| **2단계** | 모의 비행 (DRY RUN) | `python3 src/track_and_follow.py` | `dry_run: true` 상태에서 명령 계산 로그 확인, MAVLink 명령 전송 없음 |
| **3단계** | 지상 구동 점검 | `python3 src/track_and_follow.py --live` | 프로펠러 분리 상태 시동 → OFFBOARD 전환 → 모터 회전음 반응 확인 |
| **4단계** | 실전 야외 비행 | `python3 src/track_and_follow.py --live` | 이륙 호버링 확인 → OFFBOARD 전환 → 자율 추적 비행 |

### 4단계 실전 비행 상세 지침

1. **안전거리 확보**: 장애물이 없는 넓은 야외에서 조종자 및 관람자와 20m 이상 안전거리를 확보합니다.
2. **이륙 및 수동 정지비행**: 조종기로 **POSITION(POSCTL)** 모드에서 시동을 걸어 고도 5~8m로 안전하게 이륙시킨 후 기체 안정성을 확인합니다.
3. **스크립트 실행**: SSH 터미널에서 `python3 src/track_and_follow.py --live` 명령을 실행합니다 (`OFFBOARD 아님` 로그 확인).
4. **OFFBOARD 전환**: 조종기의 모드 스위치를 **OFFBOARD**로 전환하여 자율 추적을 시작합니다.
5. **수동 제어권 확보 (비상 조치)**: 기체 비행 이상 발생 시 **즉시 조종기 스위치를 POSITION(POSCTL) 모드로 복귀**시키세요.

> [!IMPORTANT]
> **조종기 비행 모드 스위치는 최우선 제어권을 갖습니다.** OFFBOARD 모드를 벗어나면 추적 스크립트는 MAVLink 명령 전송을 즉시 중단합니다.

## 4. `config.yaml` 주요 파라미터 현황 (1~2 fps 전제)

| 설정 항목 | 현재 설정값 | 1~2 fps 기준 튜닝 이유 |
| :--- | :--- | :--- |
| `camera.fps` | `2` | AI 카메라 실측 1~2 fps 동작 반영 |
| `control.lateral_gain` | `0.5` | 피드백 지연에 따른 헌팅 방지를 위해 게인 절반 하향 |
| `control.max_lateral` | `0.4` (m/s) | 1초당 최대 이동 거리를 0.4m로 안전 제한 |
| `control.stale_stop` | `1.2` (초) | 프레임 간격 사이 감속 정지 유도 |
| `tracking.smoothing` | `0.8` | 프레임이 귀하므로 평활화 지연 최소화 |
| `tracking.lost_timeout` | `3.0` (초) | 1~2프레임 순간 미검출 시 추적 포기 방지 |
| `release.hold_seconds` | `2.0` (초) | 과녁 정렬 상태에서 2~4프레임 검증 후 투하 |

## 5. 파라미터 튜닝 가이드

### 증상별 튜닝 가이드

| 증상                | 추정 원인       | 조정 파라미터 및 방안                                         |
| :---------------- | :---------- | :--------------------------------------------------- |
| 목표를 자주 놓침         | 검출 임계값 과다   | `detection.threshold` ↓ (0.50 → 0.35)                |
| 엉뚱한 물체를 목표로 잡음    | 검출 임계값 협소   | `detection.threshold` ↑ (0.50 → 0.65)                |
| 다중 물체 간 목표가 튐     | 선택 전략 미흡    | `tracking.select: nearest` 설정                        |
| 목표 상공에서 원을 그리며 선회 | 수평 게인 과다    | `lateral_gain`, `forward_gain` ↓ (0.5 → 0.3)         |
| 이동 속도가 지나치게 느림    | 감쇠 제어 과다    | `stale_stop` ↑ (1.2 → 1.6) (게인은 유지)                  |
| 중심 위치에서 잘게 떨림     | 데드밴드 협소     | `deadband` ↑ (0.08 → 0.12)                           |
| 좌우로 가야 하는데 앞뒤로 이동 | 카메라 90° 오장착 | 카메라 상단이 기수를 향하는지 재확인 (조치는 배선이 아닌 장착 방향)              |
| 하강 중 멈췄다 다시 상승    | 고도 게인 과다    | `vertical_gain` ↓, `size_deadband` ↑                 |
| 목표가 화면 밖으로 자주 이탈  | 고도 부족 또는 과속 | 비행 고도 상승, `max_lateral` ↓                            |
| 목표에 너무 낮게 내려옴     | 목표 크기 과다    | `target_size` ↓ (0.35 → 0.25)                        |
| 목표 일시 분실 시 급정지    | 분실 판정 시간 부족 | `tracking.lost_timeout` ↑ (3.0 → 4.0)                |
| 투하 조건이 통과되지 않음    | 정렬 조건 과엄    | `release.align` ↑ (0.10 → 0.15), `release.max_age` ↑ |
| **움직였다 멈췄다를 반복함** | **정상 동작**   | **조치 불필요.** 느린 카메라에 맞춘 의도된 거동입니다                     |

> [!WARNING]
> **느린 반응을 게인(gain) 상승으로 보완하려 하지 마세요.** 느린 피드백에 센 게인을 물리면 드론이 좌우로 거칠게 흔들리게(헌팅) 됩니다. 반응성을 높이고 싶다면 게인 대신 `stale_stop`을 미세하게 늘리세요.

### 권장 튜닝 순서

1. `vertical_gain: 0`으로 두고 고도는 조종자가 수동 유지합니다. `lateral_gain`과 `forward_gain`을 0.3부터 올리며 **목표 상공에 안정적으로 정지 비행하는 성능**부터 맞춥니다.
2. 수평 추적이 안정되면 `vertical_gain`을 0.2부터 단계적으로 높여 **자동 고도 강하**를 활성화합니다.
3. `target_size`를 키우면 최종 접근 고도가 낮아집니다. **한 번에 0.05씩만** 조정하세요.

> 게인을 높이다가 헌팅이 발생하면 **헌팅이 시작된 게인값의 절반으로 되돌리는 것**이 현장 튜닝의 기본 지침입니다.

## 6. 필수 비행 안전수칙

1. **프로펠러 분리 사전 점검**: 1~3단계 사전 테스트 시 프로펠러를 반드시 제거하세요.
2. **안전요원 및 조종자 배치**: 비행 중 항상 수동 전환이 가능한 조종자가 조종기를 쥐고 대기하세요.
3. **안전거리 유지**: 사람 및 구조물과 20m 이상 안전거리를 확보하세요.
4. **배터리 관리**: 배터리 잔량 30% 이하 시 테스트를 중단하고 충전하세요.
5. **초기 한계값 설정**: 최초 비행 시에는 `max_lateral: 0.3`, `max_forward: 0.3`으로 속도 한계를 더 낮추어 테스트하세요.
