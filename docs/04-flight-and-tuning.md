# 04. 비행 & 파라미터 튜닝

본 문서에서는 **하방 카메라로 지상의 목표물을 자율 추적하는 비행**을 다룹니다.
아직 전용 모델을 학습하기 전이므로, 기본 COCO 모델이 감지할 수 있는 물체(`person`, `sports ball`, `bottle` 등)를 바닥에 두고 목표물로 사용합니다.
직접 학습한 과녁 모델로 교체하는 방법은 [05. 내 모델 만들기](05-custom-model.md)에서 이어집니다.

## 카메라 장착 지침

- 카메라는 **수직 아래 방향(연직)** 을 향하도록 고정합니다.
- **카메라 상단 표시가 드론의 전방(기수 방향)** 을 향하도록 장착하세요. 카메라 영상의 상/하 축이 기체의 전/후 이동 축과 완벽히 일치해야 합니다. 카메라가 90° 회전되어 장착될 경우 좌우 이동 명령 시 기체가 앞뒤로 움직이는 오류가 발생합니다.

## 제어 구조

하방 카메라 영상에서 감지된 목표물 오차를 기반으로 제어 명령을 생성합니다 (관련 코드: `src/controller.py`).

```
   목표가 화면 오른쪽에 있다        →  오른쪽으로 이동한다        (right)
   목표가 화면 위쪽에 있다          →  앞으로 이동한다            (forward)
   목표 박스가 작다 (= 아직 높다)   →  고도를 낮춘다              (vertical)
```

기체 회전(Yaw)은 수행하지 않습니다. 옆으로 미끄러지듯 움직여 목표 상공에 머무는 것이 이 제어기의 성격입니다.

각 제어 축은 **P 제어(비례 제어)** 방식을 적용합니다. 측정된 오차 크기에 비례하여 제어 출력을 생성합니다.

```
명령 = 오차 × 게인 × 최대속도      (단, 최대속도를 넘지 않음)
```

제어 게인은 `config.yaml` 파일의 `control:` 설정 항목에서 변경할 수 있습니다.

## 단계별 검증 절차 (반드시 순서를 준수하세요)

### 1단계 — 책상 위 단독 점검 (프로펠러 분리 필수)

```bash
python3 tools/preview.py --fps 2
```

노트북 브라우저에서 `http://drone.local:8080`에 접속합니다.
카메라 아래에서 목표물을 좌우로 움직이며 계산되는 `right`(좌우 이동) 제어값의 부호가 정상인지 확인합니다.
목표물이 화면 **오른쪽**으로 이동하면 `right` 제어값이 **플러스(+)** 로 출력되어야 합니다.
목표물을 화면 **위쪽**으로 옮기면 `fwd` 값이 **플러스(+)** 여야 합니다. 이 두 축이 서로 바뀌어 나오면 카메라가 90° 돌아간 상태입니다.

### 2단계 — 모의 비행 테스트 (DRY RUN: 프로펠러 분리, FC 연결)

`config.yaml` 파일의 `dry_run: true` (기본값) 설정을 확인한 후 아래 명령을 실행합니다:

```bash
python3 src/track_and_follow.py
```

```
[OK] x=+0.42 y=-0.11 size=0.21 conf=0.78 -> fwd=+0.11 right=+0.34 down=+0.06m/s yaw=+0.0deg/s | GUIDED 아님 (현재 LOITER)
```

제어 명령은 실시간 계산되지만 비행 컨트롤러로 **실제 명령은 전송되지 않습니다.** 출력되는 제어 수치가 정상 범위인지 확인하세요.

### 3단계 — 지상 구동 테스트 (프로펠러 분리, 시동 및 GUIDED 설정)

프로펠러를 완벽히 제거한 상태에서 시동(Arming)을 걸고, GUIDED 모드로 전환한 뒤 `--live` 옵션을 적용해 실행합니다.
목표 위치 변화에 따라 모터 회전음이 알맞은 방향으로 변화하는지 소리로 확인합니다.

```bash
python3 src/track_and_follow.py --live
```

### 4단계 — 실제 야외 비행 테스트

1. 장애물이 없는 **넓은 야외**에서 수행하며, 사람과 20m 이상 거리를 확보하고 안전요원을 배치하세요.
2. 목표물을 바닥에 놓고, 조종기를 사용하여 **LOITER** 모드에서 시동을 걸어 5~8m 고도로 안전하게 이륙시킵니다.
3. 기체의 정지 비행(호버링) 상태가 안정적인지 확인합니다.
4. 라즈베리파이에 접속한 SSH 터미널에서 `python3 src/track_and_follow.py --live` 명령을 실행합니다 (SSH 미리 접속 필수).
5. 조종기의 비행 모드 스위치를 **GUIDED**로 전환하면 자율 추적 제어가 시작됩니다.
6. 비행 형태가 비정상일 경우 **즉시 조종기 스위치를 LOITER 모드로 전환**하여 수동 제어권을 확보하세요.

> **어떠한 상황에서도 조종기의 모드 전환 스위치가 최우선 제어권을 갖습니다.**
> 비행 모드가 GUIDED를 벗어나면 추적 스크립트는 비행 컨트롤러로의 명령 전송을 즉시 중단합니다.

## 프레임레이트 (`camera.fps`)

수행하는 작업에 맞춰 프레임레이트(`camera.fps`)를 적절히 설정해야 합니다.

| 작업               | 권장 fps      | preview |
| ---------------- | ----------- | ------- |
| 브라우저로 보며 튜닝      | 2 ~ 5       | 실행      |
| DRY RUN / 지상 테스트 | 5 ~ 12      | 종료      |
| **실비행**          | **10 ~ 15** | 종료      |

**실제 비행 중에는 `camera.fps`를 10 fps 미만으로 설정하지 마세요.**
하방 카메라는 기체가 조금만 기울어도 화면 속 목표 위치가 크게 밀립니다. fps가 2로 낮아지면 `max_lateral: 1.0` 조건에서도 다음 프레임이 들어올 때까지 기체가 0.5m나 이동하게 됩니다.
5m 고도에서 화각 78° 기준 화면 폭이 약 8m이므로, 단 한 프레임 사이에 목표물이 화면 너비의 6% 이상 밀려납니다.
이로 인해 목표 지점을 오버슈트하여 헌팅(진동) 현상이 발생하며, 이를 막으려고 게인을 낮추면 목표 추적 반응 속도가 너무 느려집니다.

낮은 fps 설정이 필요한 상황은 영상 미리보기 화면을 렌더링하는 작업에 한정됩니다.
실제 비행 중에는 preview 프로세스를 종료하므로 라즈베리파이의 연산 부하가 크게 줄어들어 Zero W 환경에서도 10~15 fps 속도를 안정적으로 유지할 수 있습니다.

### 카메라 fps와 MAVLink 전송 주기는 별개입니다

```
[카메라 스레드]  검출 → 추적 → 목표 저장       ← camera.fps 속도
[메인 루프]      목표 → P제어 → MAVLink 전송   ← mavlink.send_rate 속도
```

`camera.fps` 설정을 낮추더라도 MAVLink 속도 제어 명령은 `mavlink.send_rate`에 지정된 고정 주기에 따라 지속적으로 전송됩니다.

카메라 영상 수신이 중단되는 상황(케이블 이탈 등)이 발생하면 메인 루프에서 이를 감지하여 정지 명령 제어로 자동 전환합니다.

## 튜닝 가이드

제어 성능 튜닝은 `config.yaml` 파일의 파라미터를 수정하여 진행합니다. **파라미터 변경 시에는 한 번에 하나의 값만 수정하며 테스트**하세요.

### 잘 못 찾을 때

| 증상                  | 확인 및 조치 파라미터                   |
| ------------------- | ------------------------------------ |
| 목표를 자주 놓침           | `detection.threshold` ↓ (0.5 → 0.35) |
| 엉뚱한 물체를 목표로 잡음      | `detection.threshold` ↑ (0.5 → 0.65) |
| 여러 개 중 계속 다른 것으로 튐  | `tracking.select: nearest` 설정      |
| 추적 반응이 느림           | `camera.fps` ↑ (12 → 15)             |

### 움직임이 이상할 때

| 증상              | 원인       | 확인 및 조치 파라미터                 |
| --------------- | -------- | ---------------------------------- |
| 목표 위에서 원을 그리며 선회함 | 수평 게인 과다 | `lateral_gain`, `forward_gain` ↓ (1.0 → 0.6) |
| 목표를 못 쫓아감 (느림)  | 게인 부족   | `lateral_gain`, `forward_gain` ↑ (1.0 → 1.4) |
| 좌우로 이동해야 하나 앞뒤로 이동함 | 카메라 90° 오장착 | 카메라 장착 방향 재확인 및 보정 |
| 중심에서 잘게 떨림      | 데드밴드 협소 | `deadband` ↑ (0.08 → 0.12)         |
| 반응이 뚝뚝 끊김       | 평활화 과다   | `tracking.smoothing` ↑ (0.4 → 0.6) |
| 하강 중 멈추고 다시 상승함 | 고도 게인 과다 | `vertical_gain` ↓, `size_deadband` ↑ |
| 목표가 화면 밖으로 자주 이탈함 | 고도 과저 또는 속도 과속 | 고도 상승 설정, `max_lateral` ↓ |
| 목표에 너무 낮게 내려옴   |          | `target_size` ↓ (0.35 → 0.25)      |
| 목표 일시 분실 시 급정지  |          | `lost_timeout` ↑ (1.0 → 1.5)       |

### 추천 튜닝 순서

1. `vertical_gain: 0`으로 설정하여 고도는 조종자가 수동 유지하고, `lateral_gain`과 `forward_gain` 값을 0.5부터 올리면서 **목표 상공에 안정적으로 정지 호버링하는 성능**부터 맞춥니다.
2. 수평 위치 추적이 안정되면 `vertical_gain`을 0.3부터 단계적으로 높여 **자동 고도 강하 제어**를 활성화합니다.
3. `target_size` 설정값을 늘리면 목표 고도가 낮아집니다. 파라미터는 **한 번에 0.05 단위로 미세 조정**하세요.

> 게인을 점진적으로 높이다가 기체 진동(헌팅)이 발생하면, **진동이 발생한 게인값의 절반 수준으로 다시 낮추는 것**이 현장 튜닝의 기본 지침입니다.
> 하방 카메라는 기체 기울임(Roll/Pitch) 동작에 의해 영상 위치 흔들림이 큽니다. 비행 중 기체 흔들림이 발생하면 게인을 무작정 올리지 마시고 **먼저 게인값을 낮추어 테스트**해 보세요.

## 필수 비행 안전수칙

- 프로펠러를 분리한 상태에서 1~3단계 사전 점검을 반드시 완료하세요.
- 비행 중에는 항상 비행 조종기를 지닌 안전 담당자가 대기해야 합니다 (GUIDED 모드 해제 담당).
- 지오펜스(`FENCE_*`) 파라미터 안전장치를 반드시 활성화하세요.
- 사람을 목표물로 설정할 경우 기체가 사람 머리 위로 하강하므로, `target_size` 값을 작게 잡아 충분한 고도를 유지하고 되도록 사람이 아닌 물체를 목표로 사용하세요.
- 배터리 잔량이 30% 이하인 상태에서는 새로운 비행 테스트를 진행하지 마세요.
- 최초 비행 시에는 `max_lateral: 0.5`, `max_forward: 0.5`와 같이 제어 한계 수치를 낮게 설정하여 안전하게 시작하세요.
