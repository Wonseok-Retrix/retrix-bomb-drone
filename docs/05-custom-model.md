# 05. 사용자 정의 객체 감지 모델 생성 (파인튜닝)

기본 AI 모델은 COCO 데이터셋 기준 80종의 물체만 감지할 수 있습니다. 본 문서에서는 직접 수집한 이미지로 모델을 파인튜닝하여 지정한 **과녁**을 감지하고 추적하도록 구현합니다.

## 전체 흐름

```
[내 폰]   사진 200~300장 촬영
   ↓
[Roboflow] 박스 라벨링 → YOLO 형식으로 export
   ↓
[Colab]   notebooks/finetune_imx500_yolo.ipynb 실행
          학습 → 양자화 → packerOut.zip
   ↓
[Pi]      imx500-package -i packerOut.zip -o .
          → network.rpk
   ↓
[드론]    config.yaml 수정 → 추적 비행
```

> 모델 포장 도구(`imx500-tools`)는 ARM 아키텍처 전용이므로 x86 기반인 Google Colab 환경에서는 실행되지 않습니다.
> 따라서 Colab에서는 `packerOut.zip` 파일 생성까지 진행하고, 최종 패키징 명령어 한 줄만 라즈베리파이에서 실행합니다.

## 1. 학습 데이터 수집

**데이터 수집 품질이 최종 모델 성능을 좌우합니다.** 학습 알고리즘보다 양질의 데이터셋 구성이 훨씬 중요합니다.

- 클래스당 **최소 100장, 권장 200~300장**의 이미지를 준비하세요.
- **드론 시점(상공에서 아래로 내려다보는 탑뷰 각도) 촬영 사진을 반드시 포함**해야 합니다.
  (이 각도의 데이터가 없으면 지상 책상 테스트에서는 잘 작동하더라도 실제 비행 중 감지에 실패합니다)
- 촬영 거리를 다양하게 구성하세요: 근거리 / 중거리 / 원거리
- 조명 조건을 다양하게 반영하세요: 실내 / 야외 직사광선 / 그늘
- 다양한 배경에서 촬영하세요: 잔디밭 / 아스팔트 / 실내 바닥
- 목표물이 **포함되지 않은 배경 사진**도 전체의 10~20% 비율로 포함하세요 (오검출 방지 효과).

## 2. 데이터 라벨링 (Roboflow 활용)

1. https://roboflow.com 웹사이트에 가입합니다 (무료 계정 활용 가능).
2. New Project 생성 → 프로젝트 유형을 **Object Detection**으로 선택합니다.
3. 수집한 이미지를 업로드하고 감지 대상 물체마다 바운딩 박스를 지정합니다.
4. Generate 단계 진행 → 데이터 증강(Augmentation)은 Flip, Brightness 조정 정도로 최소화하여 설정합니다.
5. Export Data 선택 → 포맷으로 **YOLOv11** 선택 → *show download code* 클릭 후 다운로드 코드를 복사합니다.

## 3. Google Colab 기반 모델 학습

`notebooks/finetune_imx500_yolo.ipynb` 노트북 파일을 Google Colab에 업로드한 후 순서대로 셀을 실행합니다.

- 런타임 유형을 **T4 GPU**로 변경하는 것을 잊지 마세요.
- 3번 셀의 `EPOCHS`, `IMGSZ`, `BATCH` 파라미터는 학생들이 직접 변경하며 실험해볼 수 있는 주요 항목입니다.
- 5번 셀 평가지표에서 **mAP50 ≥ 0.7** 이상을 달성해야 실전 비행에 적용할 수 있습니다.

학습 시간 기준 (T4 GPU, 300장, 60 epoch): **약 15분 소요**
변환 및 양자화 시간: **약 15분 소요** (변환 툴 자동 설치 과정 포함)

## 4. 라즈베리파이 탑재 및 모델 설정

Colab에서 다운로드한 `my_tracker_imx500.zip` 파일을 라즈베리파이로 복사한 후 터미널에서 다음 명령을 실행합니다:

```bash
mkdir -p ~/models && cd ~/models
unzip ~/my_tracker_imx500.zip

imx500-package -i packerOut.zip -o .
# -> ~/models/network.rpk 생성됨

cp labels.txt ~/ai-tracking-drone/assets/my_labels.txt
```

`config.yaml` 파일 파라미터 수정:

```yaml
camera:
  model: /home/pi/models/network.rpk
  labels: assets/my_labels.txt

detection:
  target_class: my_marker     # labels.txt 안의 이름과 정확히 동일하게
  threshold: 0.45
  bbox_normalization: true    # YOLO 계열은 반드시 true
  bbox_order: xy              # YOLO 계열은 반드시 xy
  postprocess: ""
```

카메라 작동 확인:

```bash
python3 tools/check_camera.py
```

새로운 모델 파일(.rpk)을 처음 로드할 때도 카메라 펌웨어 업로드 과정으로 인해 1~2분 정도 소요됩니다.

## 5. 하방 카메라 기반 과녁 정밀 추적

현재 단계까지는 감지 모델만 교체된 상태이며, 드론은 여전히 **전방을 주시하며** 추적을 수행합니다.
지상의 과녁을 추적하려면 카메라 설치 방향을 하방으로 변경하고, 제어 알고리즘 모드도 전환해야 합니다.

### 하방 카메라 장착 지침

- 카메라는 **수직 아래 방향(연직)** 을 향하도록 고정합니다.
- **카메라 상단 표시가 드론의 전방(기수 방향)** 을 향하도록 장착하세요. 카메라 영상의 상/하 축이 기체의 전/후 이동 축과 완벽히 일치해야 합니다. 카메라가 90° 회전되어 장착될 경우 좌우 이동 명령 시 기체가 앞뒤로 움직이는 오류가 발생합니다.

### 제어 모드 전환

```yaml
control:
  mode: down          # front -> down
```

`config.yaml` 모드를 변경하면 `src/controller_down.py` 모듈이 적용되어 실행됩니다.
기존 `control.front:` 블록의 튜닝값은 유지되지만 하방 추적 모드에서는 영향을 주지 않습니다.

```
   과녁이 화면 오른쪽에 있다      →  오른쪽으로 이동한다        (right)
   과녁이 화면 위쪽에 있다        →  앞으로 이동한다            (forward)
   과녁 박스가 작다 (= 아직 높다) →  고도를 낮춘다              (vertical)
```

하방 추적 시에는 기체 회전(Yaw)을 수행하지 않습니다. **"바운딩 박스가 작다 = 거리가 멀다 = 목표로 접근한다"**는 제어 원칙은 전방 사람 추적과 동일하며, 접근 방향이 전방이 아닌 아래쪽(고도 강하)으로 적용됩니다.

### 하방 제어 튜닝 순서

[04. 비행 & 튜닝](04-flight-and-tuning.md) 절차와 동일하게 `preview.py` 검증 → DRY RUN → 실제 비행 순서를 엄격히 준수하세요.
하방 제어 게인은 `config.yaml`의 `control.down:` 블록에서 설정합니다.

1. `vertical_gain: 0`으로 설정하여 고도는 조종자가 수동 유지하고, `lateral_gain`과 `forward_gain` 값을 0.5부터 올리면서 **과녁 상공에 안정적으로 정지 호버링하는 성능**부터 맞춥니다.
2. 수평 위치 추적이 안정되면 `vertical_gain`을 0.3부터 단계적으로 높여 **자동 고도 강하 제어**를 활성화합니다.
3. `target_size` 설정값을 늘리면 목표 고도가 낮아집니다. 파라미터는 **한 번에 0.05 단위로 미세 조정**하세요.

| 증상 | 원인 | 확인 및 조치 사항 |
|---|---|---|
| 과녁 위에서 원을 그리며 선회함 | 수평 게인 과다 | `lateral_gain`, `forward_gain` 설정값을 함께 하향 조정 |
| 좌우로 이동해야 하나 앞뒤로 이동함 | 카메라 90° 오장착 | 카메라 장착 방향 재확인 및 보정 |
| 하강 중 멈추고 다시 상승함 | 고도 게인 과다 | `vertical_gain` ↓, `size_deadband` ↑ |
| 과녁이 화면 밖으로 자주 이탈함 | 고도 과저 또는 속도 과속 | 고도 상승 설정, `max_lateral` ↓ |

> 하방 카메라는 기체 기울임(Roll/Pitch) 동작에 의해 영상 위치 흔들림이 큽니다.
> 따라서 `control.down:`의 기본 게인 및 제어 한계값은 `front` 모드보다 낮게 정밀 설정되어 있습니다.
> 비행 중 기체 흔들림이 발생하면 게인을 무작정 올리지 마시고 **먼저 게인값을 낮추어 테스트**해 보세요.

## 6. 목표 과녁 투하 제어 (서보 드로퍼)

서보 드로퍼는 **비행 컨트롤러(FC)를 거치지 않고 라즈베리파이 GPIO 핀에서 직접** 제어합니다.
FC에서는 5V 전원만 공급받으며, 상세 배선 방식은 [01. 배선 3](01-hardware.md#배선-3-서보-드로퍼-과녁-투하용-2일차) 섹션을 참조하세요.

### 1) 서보 작동 각도 측정 (지상 점검)

```bash
python3 tools/check_dropper.py --angle 0
python3 tools/check_dropper.py --angle 80
```

투하 물품이 **고정되는 각도(closed_angle)** 와 **투하되는 각도(open_angle)** 를 측정하여 `config.yaml` 파일에 반영합니다.

```yaml
dropper:
  closed_angle: 0     # 잡고 있는 각도
  open_angle: 80      # 놓는 각도
```

각도 설정 후 아래 명령어로 구동을 반복 테스트합니다. 반드시 투하할 물품을 실제로 체결한 상태에서 검증하세요.

```bash
python3 tools/check_dropper.py
```

### 2) 투하 판단 조건 설정

투하 시점 판단은 `src/release.py` 모듈에서 담당합니다. 총 4가지 조건이 만족되어야 하며, **조건 중 하나라도 해제되면 대기 타이머가 0으로 리셋**됩니다.

```
  1. 과녁이 보인다
  2. 과녁이 화면 중앙에 있다        →  release.align
  3. 충분히 낮게 내려왔다           →  release.size_min  (박스 크기)
  4. 위 상태가 계속 유지됐다        →  release.hold_seconds
```

기체가 이동 중 우연히 중앙을 순간 통과할 때 오투하되는 현상을 방지하기 위해 4번 유지 시간 조건이 필수적으로 동작합니다.

```yaml
dropper:
  enable: true        # ★ 지상 점검을 마친 뒤에 켜세요
  once: true          # 한 비행에 한 번만
  release:
    align: 0.10       # 작을수록 정확 / 대신 조건을 못 맞춰 못 놓을 수 있음
    size_min: 0.30    # 클수록 낮게 내려와서 놓음
    hold_seconds: 1.0
```

> 드로퍼 위치가 카메라 렌즈 바로 아래에 위치하지 않는 경우 `aim_x`, `aim_y` 파라미터로 조준점을 오프셋 조정합니다.
> 예컨대 드로퍼가 카메라보다 **후방**에 위치한다면 과녁이 화면 **상단**에 위치할 때 투하해야 하므로 `aim_y`를 음수(-) 값으로 지정합니다. 실전 던지기 테스트를 통해 미세 조정하는 것이 가장 효과적입니다.

투하 조건 판단 알고리즘은 **`mode: down` 및 `dropper.enable: true` 조건이 모두 충족될 때만 활성화**됩니다.
전방 사람 추적 모드(`mode: front`)에서는 설정과 무관하게 서보 드로퍼가 절대 동작하지 않습니다.
또한 `dry_run: true` 상태에서는 서보가 실제로 작동하지 않고 조건 충족 여부 로그만 출력됩니다.

### 3) 단계별 투하 검증 절차

| 단계 | 수행 작업 | 확인 및 검증 사항 |
|---|---|---|
| 1 | `check_dropper.py` (책상 점검, 프로펠러 분리) | 설정한 두 각도 사이를 원활히 오가는가 |
| 2 | `enable: true` + DRY RUN 설정 후 과녁을 들고 카메라 앞에서 이동 | 실행 로그의 `드로퍼:` 항목이 중앙 위치에 도달했을 때만 조건을 충족하는가 |
| 3 | 프로펠러 분리 상태 시동 + GUIDED 모드 전환 | 실제로 서보 드로퍼가 개방 작동하는가 |
| 4 | 실제 비행 — 저고도에서 가벼운 물품부터 테스트 | 목표 과녁 근처로 정확히 투하되는가 |

프로그램 실행 중 투하 조건 판단 로그 예시는 다음과 같습니다:

```
[OK] x=+0.03 y=-0.02 size=0.33 conf=0.81 -> fwd=+0.00 right=+0.00 down=+0.02m/s yaw=+0.0deg/s | OK
     드로퍼: 정렬 유지중 0.6/1.0s
```

### 문제 해결 (투하 동작 오류 발생 시)

| 증상 | 원인 | 해결 방안 |
|---|---|---|
| 서보가 구동되지 않음 | GND(접지) 분리 상태 | FC, 서보, Pi의 GND를 공통 접지로 연결 |
| 서보에 지속적인 떨림 발생 | 공급 전원 부족 | FC 서보 레일 5V 전압 확인, Pi 5V 핀 직렬 공급 금지 |
| 서보 구동 각도가 설정과 다름 | 서보 모듈 펄스 폭 특성 차이 | `min_pulse_us` / `max_pulse_us` 파라미터 조절 |
| 투하 동작이 수행되지 않음 | 조건 파라미터가 과도하게 엄격함 | `align` ↑ (0.10 → 0.15), `hold_seconds` ↓ |
| 오투하 발생 | 조건 파라미터가 과도하게 완화됨 | `align` ↓, `size_min` ↑ |
| 투하 지점이 항상 일정한 방향으로 편차 발생 | 드로퍼 장치와 카메라 장착 위치 오차 | `aim_x` / `aim_y` 파라미터로 조준점 보정 |
| 전방으로 물품이 쏠려 투하됨 | 투하 시점에 기체 전진 관성 잔재 | `hold_seconds` ↑ (완전 정지 후 투하되도록 조정) |

### 투하 작업 필수 안전수칙

- **사람, 차량, 건물 상공에서는 절대로 물품을 투하하지 마세요.** 반드시 넓고 안전한 야외에서만 테스트하세요.
- 투하 물품은 탁구공, 콩주머니 등 가볍고 충격을 주지 않는 부드러운 재질을 사용하세요. 단단하거나 무거운 물품 투하는 엄격히 금지됩니다.
- 서보 드로퍼 장치 및 투하 물품은 기체의 무게중심(CoG) 근처에 위치시키고, 프로펠러 회전 영역 하단에 안전하게 배치하세요.
- 물품 투하 직후 기체 중량이 급격히 줄어들어 **순간적으로 고도가 상승할 수 있으므로** 조종자는 즉시 고도 제어 조종을 준비하세요.
- 최초 투하 시도 시에는 `once: true` 파라미터를 유지하여 중복 투하 사고를 예방하세요.
