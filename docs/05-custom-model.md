# 05. 사용자 정의 객체 감지 모델 생성 (파인튜닝)

기본 AI 모델은 COCO 데이터셋 기준 80종의 물체만 감지할 수 있습니다. 
이 문서에서는 직접 수집한 이미지로 모델을 파인튜닝하여, 지정한 **과녁**을 감지하고 추적하도록 구현합니다.

## 전체 흐름

```
[핸드폰]   사진 촬영 (최소 10장 이상 권장)
   ↓
[Roboflow] 폴리곤 라벨링 → YOLO 형식으로 export
   ↓
[Colab]   notebooks/finetune_imx500_yolo.ipynb 실행
          데이터 augmentation → 학습 → 양자화 → packerOut.zip
   ↓
[Pi]      imx500-package -i packerOut.zip -o .
          → network.rpk
   ↓
[드론]    config.yaml 수정 → 추적 비행
```

> 모델 포장 도구(`imx500-tools`)는 ARM 아키텍처 전용이므로 x86 기반인 Google Colab 환경에서는 실행되지 않습니다.
> 따라서 Colab에서는 `packerOut.zip` 파일 생성까지 진행하고, 최종 패키징 명령어 한 줄만 라즈베리파이에서 실행합니다.

---

## 1. 학습 데이터 수집

사진은 **10~15장이면 충분**합니다. 다만 **오려내기가 잘 되는 사진**이어야 하므로 다음 사항을 지키세요.

- 과녁이 **크고 선명하게** 찍혀야 합니다. 오려낸 조각의 품질이 최종 성능을 좌우합니다.
- 사진 한 장에는 **과녁 하나만** 담고, 배경에 비슷한 색의 물체가 함께 찍히지 않도록 하세요.
- 다양한 조명 환경에서 촬영하세요: 실내 / 야외 직사광선 / 그늘
- 과녁을 여러 방향으로 돌려 가며 촬영하세요.
- 촬영 거리나 각도는 크게 신경 쓰지 않아도 됩니다. 거리·회전·기울기 변화는 노트북이 합성 단계에서 만들어 냅니다.

**비행 현장의 배경 사진**(과녁이 없는 사진)을 따로 몇 장 찍어 두면 오검출을 줄이는 데 도움이 됩니다. 노트북 4번 단계의 `/content/backgrounds`에 넣어 사용합니다.

## 2. 데이터 라벨링 (Roboflow 활용)

1. https://roboflow.com 웹사이트에 가입합니다 (무료 계정 사용 가능).
2. New Project 생성 → 프로젝트 유형을 **Instance Segmentation**으로 선택합니다.
3. 수집한 이미지를 업로드하고 **Polygon Tool로 과녁의 외곽선을 따라** 그립니다.
4. Generate 단계 진행 → 데이터 증강(Augmentation)은 **모두 끄세요.** 증강은 노트북이 훨씬 강하게 수행합니다.
5. 좌측 Dataset 탭 선택 후 모든 이미지 선택 → Export Data → Download Dataset → 포맷으로 **YOLOv11** 선택 → Export AS → Code Snippet → *show download code* 클릭 후 다운로드 코드를 복사합니다.

> 바운딩 박스(Object Detection)로 라벨링해도 동작합니다. 이 경우 노트북이 박스 안에서 색을 기준으로 과녁을 추출하며, 실패하면 GrabCut으로 자동 전환합니다.
> 다만 **폴리곤이 곧 정확한 외곽선**이므로 추정 과정이 없는 폴리곤 라벨링을 권장합니다.

## 3. Google Colab 기반 모델 학습

`notebooks/finetune_imx500_yolo.ipynb` 노트북 파일을 Google Colab에 업로드한 후 순서대로 셀을 실행합니다.

- 런타임 유형을 **T4 GPU**로 변경하는 것을 잊지 마세요.
- **3-1 오려내기 결과 확인이 가장 중요한 단계입니다.** 모양이 온전하게 잘린 조각만 `KEEP`에 남기세요.
- **5-1 미리보기**에서 초록 박스가 과녁에 정확히 붙어 있는지 확인한 뒤 데이터를 생성하세요.
- 6번 셀의 `EPOCHS`, `BATCH`, `FREEZE`와 5번 셀의 `SCALE_RANGE`, `P_DISTRACTOR`는 학생들이 직접 바꿔 가며 실험할 수 있는 항목입니다.
- 8번 셀의 mAP50이 실제 성능입니다. **0.7 이상**이면 비행에 적용할 수 있습니다.

소요 시간 (T4 GPU): 합성 데이터 생성 **약 3분**, 학습 **약 15분**, 변환 및 양자화 **약 15분** (변환 툴 설치 과정 포함)

## 4. 라즈베리파이 탑재 및 모델 설정

Colab에서 다운로드한 `icon_tracker_imx500.zip` 파일을 라즈베리파이로 복사합니다. **내 PC의 터미널**에서 실행하세요 (파일이 받아진 폴더 기준):

```bash
scp icon_tracker_imx500.zip pi@drone.local:~/
```

> `drone.local` 접속이 안 되면 라즈베리파이에서 `hostname -I`로 IP를 확인한 뒤 `scp icon_tracker_imx500.zip pi@192.168.x.x:~/` 형태로 실행하세요.
> 윈도우는 PowerShell에서 동일한 명령을 사용할 수 있습니다.

이후 **라즈베리파이 SSH 터미널**에서 다음 명령을 실행합니다:

```bash
mkdir -p ~/models && cd ~/models
unzip ~/icon_tracker_imx500.zip

imx500-package -i packerOut.zip -o .
# -> ~/models/network.rpk 생성됨

cp labels.txt ~/ai-tracking-drone/assets/my_labels.txt
```

`config.yaml` 파일 파라미터 수정:

```yaml
camera:
  model: /home/pi/models/network.rpk
  labels: assets/my_labels.txt

detection:
  target_class: my_marker     # labels.txt 안의 이름과 정확히 동일하게
  threshold: 0.45
  bbox_normalization: true    # YOLO 계열은 반드시 true
  bbox_order: xy              # YOLO 계열은 반드시 xy
  postprocess: ""
```

카메라 작동 확인:

```bash
python3 tools/check_camera.py
```

새로운 모델 파일(.rpk)을 처음 로드할 때도 카메라 펌웨어 업로드 과정으로 인해 1~2분 정도 소요됩니다.

## 5. 과녁 추적 재튜닝

모델만 교체되었을 뿐 제어기와 카메라 장착 방식은 그대로입니다.
[04. 비행 & 튜닝](04-flight-and-tuning.md) 절차와 동일하게 `preview.py` 검증 → DRY RUN → 실제 비행 순서를 엄격히 준수하며 게인을 다시 확인하세요.

과녁은 기본 모델로 쓰던 목표물과 크기·모양이 다르므로 다음 두 값이 특히 달라집니다.

- `control.target_size` — 과녁 실물 크기에 맞춰 다시 잡습니다. 값을 키우면 드론이 더 낮게 내려옵니다 (한 번에 0.05 단위).
- `detection.threshold` — 파인튜닝 모델은 확신도 분포가 다릅니다. 0.45 부근에서 시작해 오검출과 미검출을 보며 조정하세요.

## 6. 목표 과녁 투하 제어 (서보 드로퍼)

서보 드로퍼는 **비행 컨트롤러(FC)를 거치지 않고 라즈베리파이 GPIO 핀에서 직접** 제어합니다.
FC에서는 5V 전원만 공급받으며, 상세 배선 방식은 [01. 배선 3](01-hardware.md#배선-3-서보-드로퍼-과녁-투하용-2일차) 섹션을 참조하세요.

### 1) 서보 작동 각도 측정 (지상 점검)

```bash
python3 tools/check_dropper.py --angle 0
python3 tools/check_dropper.py --angle 80
```

투하 물품이 **고정되는 각도(closed_angle)** 와 **투하되는 각도(open_angle)** 를 측정하여 `config.yaml` 파일에 반영합니다.

```yaml
dropper:
  closed_angle: 0     # 잡고 있는 각도
  open_angle: 80      # 놓는 각도
```

각도 설정 후 아래 명령어로 구동을 반복 테스트합니다. 반드시 투하할 물품을 실제로 체결한 상태에서 검증하세요.

```bash
python3 tools/check_dropper.py
```

### 2) 투하 판단 조건 설정

투하 시점 판단은 `src/release.py` 모듈에서 담당합니다. 총 4가지 조건이 만족되어야 하며, **조건 중 하나라도 해제되면 대기 타이머가 0으로 리셋**됩니다.

```
  1. 과녁이 보인다
  2. 과녁이 화면 중앙에 있다        →  release.align
  3. 충분히 낮게 내려왔다           →  release.size_min  (박스 크기)
  4. 위 상태가 계속 유지됐다        →  release.hold_seconds
```

기체가 이동 중 우연히 중앙을 순간 통과할 때 오투하되는 현상을 방지하기 위해 4번 유지 시간 조건이 필수적으로 동작합니다.

```yaml
dropper:
  enable: true        # ★ 지상 점검을 마친 뒤에 켜세요
  once: true          # 한 비행에 한 번만
  release:
    align: 0.10       # 작을수록 정확 / 대신 조건을 못 맞춰 못 놓을 수 있음
    size_min: 0.30    # 클수록 낮게 내려와서 놓음
    hold_seconds: 1.0
```

> 드로퍼 위치가 카메라 렌즈 바로 아래에 위치하지 않는 경우 `aim_x`, `aim_y` 파라미터로 조준점을 오프셋 조정합니다.
> 예컨대 드로퍼가 카메라보다 **후방**에 위치한다면 과녁이 화면 **상단**에 위치할 때 투하해야 하므로 `aim_y`를 음수(-) 값으로 지정합니다. 실전 던지기 테스트를 통해 미세 조정하는 것이 가장 효과적입니다.

투하 조건 판단 알고리즘은 **`dropper.enable: true` 일 때만 활성화**됩니다.
또한 `dry_run: true` 상태에서는 서보가 실제로 작동하지 않고 조건 충족 여부 로그만 출력됩니다.

### 3) 단계별 투하 검증 절차

| 단계 | 수행 작업 | 확인 및 검증 사항 |
|---|---|---|
| 1 | `check_dropper.py` (책상 점검, 프로펠러 분리) | 설정한 두 각도 사이를 원활히 오가는가 |
| 2 | `enable: true` + DRY RUN 설정 후 과녁을 들고 카메라 앞에서 이동 | 실행 로그의 `드로퍼:` 항목이 중앙 위치에 도달했을 때만 조건을 충족하는가 |
| 3 | 프로펠러 분리 상태 시동 + OFFBOARD 모드 전환 | 실제로 서보 드로퍼가 개방 작동하는가 |
| 4 | 실제 비행 — 저고도에서 가벼운 물품부터 테스트 | 목표 과녁 근처로 정확히 투하되는가 |

프로그램 실행 중 투하 조건 판단 로그 예시는 다음과 같습니다:

```
[OK] x=+0.03 y=-0.02 size=0.33 conf=0.81 -> fwd=+0.00 right=+0.00 down=+0.02m/s yaw=+0.0deg/s | OK
     드로퍼: 정렬 유지중 0.6/1.0s
```

### 문제 해결 (투하 동작 오류 발생 시)

| 증상 | 원인 | 해결 방안 |
|---|---|---|
| 서보가 구동되지 않음 | GND(접지) 분리 상태 | FC, 서보, Pi의 GND를 공통 접지로 연결 |
| 서보에 지속적인 떨림 발생 | 공급 전원 부족 | FC 서보 레일 5V 전압 확인, Pi 5V 핀 직렬 공급 금지 |
| 서보 구동 각도가 설정과 다름 | 서보 모듈 펄스 폭 특성 차이 | `min_pulse_us` / `max_pulse_us` 파라미터 조절 |
| 투하 동작이 수행되지 않음 | 조건 파라미터가 과도하게 엄격함 | `align` ↑ (0.10 → 0.15), `hold_seconds` ↓ |
| 오투하 발생 | 조건 파라미터가 과도하게 완화됨 | `align` ↓, `size_min` ↑ |
| 투하 지점이 항상 일정한 방향으로 편차 발생 | 드로퍼 장치와 카메라 장착 위치 오차 | `aim_x` / `aim_y` 파라미터로 조준점 보정 |
| 물품이 진행 방향으로 쏠려 투하됨 | 투하 시점에 기체 이동 관성 잔재 | `hold_seconds` ↑ (완전 정지 후 투하되도록 조정) |

### 투하 작업 필수 안전수칙

- **사람, 차량, 건물 상공에서는 절대로 물품을 투하하지 마세요.** 반드시 넓고 안전한 야외에서만 테스트하세요.
- 투하 물품은 탁구공, 콩주머니 등 가볍고 충격을 주지 않는 부드러운 재질을 사용하세요. 단단하거나 무거운 물품 투하는 엄격히 금지됩니다.
- 서보 드로퍼 장치 및 투하 물품은 기체의 무게중심(CoG) 근처에 위치시키고, 프로펠러 회전 영역 하단에 안전하게 배치하세요.
- 물품 투하 직후 기체 중량이 급격히 줄어들어 **순간적으로 고도가 상승할 수 있으므로** 조종자는 즉시 고도 제어 조종을 준비하세요.
- 최초 투하 시도 시에는 `once: true` 파라미터를 유지하여 중복 투하 사고를 예방하세요.

## 문제 해결 (기타 오류 상황)

| 증상 | 원인 | 해결 방안 |
|---|---|---|
| Colab 학습 mAP 지표가 0.3 이하로 저조함 | 오려내기 실패 또는 라벨링 오류 | 노트북 3-1의 조각 모양과 5-1의 박스 위치를 재확인 |
| 과녁과 색만 비슷한 물체를 오검출함 | 미끼(distractor) 부족 | `P_DISTRACTOR`를 0.8로 올려 재생성, `detection.threshold` 상향 |
| 지상 테스트는 되나 비행 중 감지 실패 | 원거리(작은 크기) 샘플 부족 | `SCALE_RANGE` 하한을 0.03으로 낮춰 재생성 |
| Colab 평가 지표는 높으나 카메라 감지 실패 | 8비트 양자화 연산 손실 | `IMGSZ=640` 파라미터 적용 후 재학습 |
| 감지는 수행되나 바운딩 박스 위치 오차 발생 | 바운딩 박스 관련 파라미터 설정 오류 | `bbox_normalization: true`, `bbox_order: xy` 설정 재확인 |
| 라벨 명칭이 이상하게 출력됨 | 라벨 파일 불일치 | Colab에서 생성된 `labels.txt` 사용 여부 확인 |
| `imx500-package` 명령어 미인식 | 모델 패키징 툴 미설치 | `sudo apt install imx500-all` 실행 |
| 카메라가 모델 로딩 단계에서 응답 없음 | 모델 용량 과다 | `IMGSZ=320` 파라미터 적용 후 재학습 |

## 심화 과제 (추가 실습 프로젝트)

- 감지 클래스를 2개 이상 확장하고, `target_class`를 다변화하여 상황에 따른 수율 추적을 실험해 보세요.
